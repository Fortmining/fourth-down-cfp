# Fourth Down v0.7.1 — follow and notification UX

Follow Game and Follow Team now open a named, keyboard-contained dialog. Each follow has individual kickoff, halftime, close game, scoring, final, Upset Watch and Confirmed Upset choices. Team durations remain one bound game, 24 hours or seven days. Confirm saves the follow and its choices in one authenticated server mutation. No request enables push without an explicit confirmation gesture. A watchlist-only follow without a push subscription is saved locally and explicitly described that way.

More → Following provides Manage Follow and Unfollow. More → Notifications has a sticky Save Changes bar and live persistence feedback. Unsaved settings stay in a separate durable draft; they do not replace committed device preferences or silently change delivery. Cancel, Escape, Back and in-app navigation provide Save, Discard and Continue Editing when changes exist. Full browser reload/close uses the browser's native leave confirmation, whose buttons cannot be customized; drafts survive a forced PWA shutdown where iOS does not offer a leave prompt. Reopen a follow dialog or Notifications to recover its draft.

Following-only saves preserve the server's favorite-team and ranking preferences, including while another settings draft exists. Authenticated mutations use compare-and-set so concurrent writes return a retryable conflict. Failed new follows remain drafts and do not become locally active. Existing offline unfollows retain the previous immediate local mute and pending server retry behavior. Enabling a new follow while following alerts were disabled keeps prior follows muted; review any prior follow's choices before re-enabling it.

The service worker is updated before receiving saved per-follow controls. Server persistence and a device-control failure are reported separately, with a retry marker shown on reopening Notifications. Blocked or unsupported push is explained in the follow dialog; all-off choices allow a local watchlist-only follow without requesting permission. Existing subscription capabilities and push endpoints are reused, including edits while OS permission is blocked. Permanent favorites remain separate.

Per-follow server activation timestamps prevent a newly enabled type from replaying an older event. Changing halftime preserves an existing kickoff's eligibility. Legacy v0.7 follows inherit their saved group choices; explicit follow choices override those defaults. The following master switch still pauses all temporary follows. Existing event identities, kickoff recovery bounds, final verification, AP ranking rules, cooldowns, delivery budget and durable duplicate claims are retained.

## Validation

- 125 automated regressions cover delivery, kickoff recovery, final and ranking routing, scope isolation, capability validation, concurrent saves, per-follow timestamps, worker restart/deduplication, blocked permissions, offline/rejected saves and retry markers.
- TypeScript, lint and production build are release gates.
- Mobile Chromium and WebKit automation uses an iPhone-sized browser and **simulated API/subscription controls**, not real push. Checks include modal naming and automated accessibility audit, keyboard focus containment, Back/Cancel guards, Save/Discard/Continue Editing, failed and offline save retry, game/team options, persistence after reload, sticky save visibility and 320/390px overflow.
- Native safe-area padding and dynamic viewport bounds are implemented. Real iPhone Home Screen installation, a physical notch/keyboard, VoiceOver speech, OS permission prompts and closed-PWA delivery of these new per-follow choices require physical-device confirmation. An automated accessibility audit is not a VoiceOver session.
- Production verification is read-only: check scheduler health and compare existing device preferences before/after deployment. Do not send production test pushes, manufacture live events or modify the user's subscriptions to claim validation.

Existing real evidence remains App State–JMU final delivery and the user-confirmed Duke–Virginia kickoff, with closed-PWA receipt and no-repeat evidence. The original historical App State–JMU cause remains unproven. v0.7.1 UX simulations are not new real-event delivery evidence for halftime, close game, scoring or upset alerts. Issue #5's prior real kickoff confirmation is unchanged by this release.
