v0.6 erased completed one-game follow timestamps and retained no history of selection/filtering decisions. Older Vercel request logs are outside the one-hour retention window. This release does not manufacture a historical follow time or describe a successful simulation as proof of the missed-kickoff cause.

`Inspect this device` reads the installed app's existing worker preference snapshot before any settings write. That snapshot may retain the original completed follow even after local watchlist cleanup. A capability-authenticated, same-origin report endpoint stores only normalized follow data, current permission/app context and clock comparison; it exposes no encryption keys, push endpoints or capability tokens. Inspection requests neither permission nor push subscriptions and sends no notification. Opening a desktop/Safari browser cannot read an installed iPhone PWA's private storage.

A private, bounded 30-day audit now records settings/follow snapshots, event filtering, provider acceptance/failure, duplicate suppression, completed-follow cleanup and browser display acknowledgements. Cleanup archives the original follow snapshot before removing it and preserves the record if archival fails. Audit failures do not interrupt normal alerts or explicit opt-out. New worker receipts include a version, self-reported platform and open-client count; zero clients is evidence that the worker processed the notification without an open app window, not proof of a visible OS banner. Existing workers check for code updates on app open without creating a subscription or changing consent/settings.

The four-minute scheduler, permanent favorites, v0.5 type preferences, explicit push opt-in and server/device event-ID deduplication are retained. No historical kickoff or final is replayed. Production incident evidence and user confirmation remain distinct from isolated regression fixtures.
